# cj 仓库新人导览

## 当前仓库状态

这个仓库目前是一个**初始化骨架仓库**：

- 仅包含 Git 元数据目录（`.git/`）与占位文件 `.gitkeep`。
- 还没有业务代码、构建脚本、测试代码、文档目录或工程化配置（例如 `package.json`、`pyproject.toml`、`Cargo.toml`、`Makefile` 等）。

## 对新人的意义

在当前阶段，你需要优先把这个仓库理解为一个“待搭建工程”，而不是“可直接阅读业务实现”的项目。

建议先明确以下信息，再开始深入：

1. **技术栈**：后续计划使用哪种语言与框架。
2. **项目边界**：这个仓库是服务端、前端、库、脚本工具，还是多模块 monorepo。
3. **交付目标**：首个里程碑要上线什么能力。
4. **质量基线**：测试策略、代码风格、CI/CD、发布流程。

## 推荐的后续学习路径

### 第一步：建立基础工程结构

建议尽快补齐：

- 顶层 `README.md`（项目目标、运行方式、目录说明）
- 依赖与构建清单（如 `package.json` / `pyproject.toml`）
- 测试入口（如 `tests/` 目录 + 最小可运行测试）
- 开发规范（lint / format 配置）

### 第二步：形成“可运行闭环”

至少做到：

- 一条本地启动命令
- 一条测试命令
- 一条静态检查命令
- 一条 CI 流水线（可先做最小版本）

### 第三步：沉淀新人友好文档

建议新增：

- `docs/architecture.md`：系统架构与模块关系
- `docs/contributing.md`：开发流程与提交流程
- `docs/onboarding.md`：新人一周入门路线

## 给新人的实操建议

- 不要急着“看代码细节”，先建立全局认知（目标、边界、流程）。
- 每拿到新任务，先确认输入输出、依赖模块、验证方式。
- 养成“改动即补文档/测试”的习惯，减少隐性知识。
